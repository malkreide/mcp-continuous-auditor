# Worker forward-proxy domain allowlist (tinyproxy, FilterExtended On, default-deny).
# One POSIX extended regex per line; each matches an allowed host. The Worker only
# needs: the auditor + target on GitHub, the Python/Node/Debian package sources,
# and the Zürich open-data endpoints the fixtures were recorded against.
#
# PORTFOLIO FAN-OUT (scripts/portfolio_scan.py): N target repositories need NO new
# entries — github.com below is a host match and covers all of them. What is NOT
# covered is each target's own UPSTREAM data origin: only Zürich's is listed, because
# that is the one target the fixtures were recorded against. A target that opts into
# the `boot` predicate starts its real server, and a startup that reaches an unlisted
# origin fails against this default-deny proxy in a way that reads exactly like a
# target defect. Add the origin in the same change as the target.
# See forward-proxy/README.md → "Portfolio fan-out".
(^|\.)github\.com$
(^|\.)githubusercontent\.com$
(^|\.)codeload\.github\.com$
# LOAD-BEARING FOR A GATE, not just for `uv sync`. scripts/shipped_probe.py
# installs the target's package from the index into a fresh venv and makes THAT
# prove it runs — the one check that reads what users actually install rather
# than the checkout. Remove either line and that gate stops working; because it
# fails closed it will report 127 ("the index could not be reached") rather than
# a false green, but the check is gone either way.
# tests/test_shipped_probe.py asserts both are present, so a cleanup pass that
# prunes them as unused turns CI red instead of silently disabling the gate.
(^|\.)pypi\.org$
(^|\.)files\.pythonhosted\.org$
(^|\.)registry\.npmjs\.org$
(^|\.)astral\.sh$
(^|\.)deb\.debian\.org$
(^|\.)security\.debian\.org$
(^|\.)data\.stadt-zuerich\.ch$
